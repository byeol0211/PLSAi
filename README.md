# SpecSignal

> **자격증·공모전 탐색과 일정 관리를 연결하는 모바일 우선 반응형 웹 서비스**

[웹 프로토타입](https://byeol0211.github.io/PLSAi/) · [GitHub 저장소](https://github.com/byeol0211/PLSAi)

**프로젝트 상태:** 프론트엔드 프로토타입 개발 중 · **현재 버전:** `v0.6`

> `v0.6`은 프로젝트 문서상 확정된 현재 버전이다. Git 태그나 GitHub Release는 별도 생성해야 한다.

## 프로젝트 개요

SpecSignal은 사용자의 **전공·관심 직무·준비 기간·개인 일정**을 바탕으로 국가자격증과 공모전을 탐색하고, 필요한 일정을 직접 관리하도록 돕는 서비스다. 여러 사이트에 흩어진 정보를 탐색하고, 추천받은 항목을 관심 목록이나 캘린더로 이어주는 경험을 목표로 한다.

### 해결하려는 문제

- 자격증과 공모전 정보가 여러 사이트에 분산되어 비교하기 어렵다.
- 사용자의 전공·진로·준비 여건을 고려한 탐색이 번거롭다.
- 공고를 발견해도 접수 마감일과 시험일을 개인 일정으로 관리하기 어렵다.
- 학교 학사일정과 준비 일정을 함께 고려하기 어렵다.

### 주요 사용자

- 자격증 취득과 공모전 참여를 준비하는 대학생
- 전공 및 관심 직무에 맞는 경험을 탐색하는 취업 준비생
- 학업 일정과 자격증·공모전 준비를 병행하는 사용자

| 공모전 자동 수집: n8n + Gemini 검토 | 정기 수집과 비정형 공고문 정제의 역할 분리 |

## 2. PRD — 제품 요구사항

### 핵심 사용자 흐름

1. 최초 진입 시 전공·관심 직무 등 기본 프로필 입력
2. 홈에서 **다가오는 일정** 확인 또는 **내 캘린더**로 전환
3. 자격증·공모전 목록 검색 및 상세 정보 확인
4. AI 추천 화면에서 조건을 입력해 추천 탐색 *(현재는 예시 응답)*
5. 관심 항목 저장 및 필요한 일정만 캘린더에 등록
6. 마이페이지에서 프로필·관심 목록·학사일정 관리

> 관심 저장이나 추천만으로 캘린더에 자동 등록하지 않는다. 사용자가 등록을 선택하도록 설계한다.

### 기능 요구사항

| 영역 | 목표 기능 | 현재 저장소 상태 |
|---|---|---|
| 홈 | 다가오는 일정 / 내 캘린더 전환 | 프로토타입 구현 |
| 일정 | 개인 일정 등록·조회·수정·삭제, D-day 표시 | 브라우저 저장 기반 구현 |
| 학사일정 | 학교 일정 조회·입력·관리 | 직접 입력 및 예시 조회 화면 구현; 실제 학교 연동 미구현 |
| 탐색 | 자격증·공모전 목록, 검색, 상세 | 예시 데이터 기반 구현 |
| AI 추천 | 사용자 조건을 반영한 대화형 추천 | 화면·예시 응답 구현; 실제 LLM 미연동 |
| 관심 목록 | 자격증·공모전 저장 및 해제 | 브라우저 저장 기반 구현 |
| 마이페이지 | 사용자 정보 확인·수정 | 브라우저 저장 기반 구현 |
| 공모전 등록 제안 | 공식 URL·파일 제출, 검수 후 게시 | 입력 검증·시연 화면만 구현; 서버 제출 미구현 |
| 데이터베이스 | 사용자·일정·공모전 데이터 영속화 | Supabase 연동 예정; 현재 저장소에는 미연동 |
| 공모전 자동 수집 | 정기 수집·AI 정제·검증·중복 제거 | n8n + Gemini + Supabase 도입 검토/계획 |
| 국가자격 데이터 | 공식 국가자격 API 조회 | 기존 별도 구현 이력 있음; 현재 웹 스냅샷은 예시 데이터 |

#### MVP 범위

- **Must:** 프로필 입력, 탐색·상세, 일정 CRUD, 관심 목록, 홈/캘린더, 기본 모바일 UI
- **Next:** 실제 국가자격 API 및 공모전 데이터 연동, Supabase 저장, AI 추천 API, 학사일정 입력 자동 구조화
- **Later:** 기관 직접 등록 승인 워크플로, 수집 품질 지표, 운영 관리 기능

**범위 제외:** 푸시 알림 및 알림함. 이전 기획에 있었으나 현재 모바일 우선 웹 방향에서 제외했다.

## 3. 기술 스택 및 아키텍처

| 구분 | 기술 | 비고 |
|---|---|---|
| 프론트엔드 | HTML5, CSS3, JavaScript | 모바일 우선 반응형 웹 |
| 정적 배포 | GitHub Pages | 별도 빌드 과정 없는 정적 파일 배포 |
| 현재 프로토타입 저장 | Browser `localStorage` | 기기·브라우저 간 동기화 불가 |
| 데이터베이스(계획) | Supabase / PostgreSQL | 실제 데이터 저장 및 조회 |
| AI(계획) | Gemini API | 추천 및 공고문 구조화 |
| 자동 수집(계획) | n8n, HTTP Request, HTML 추출 | 정기 수집 및 검증 워크플로 |
| 국가자격 데이터(계획) | 공공데이터포털 국가자격 API | 응답·오류 검증 필요 |
| 디자인 | Figma | 화면 기획 및 시안 |

```text
[사용자 브라우저]
    ├─ 현재: HTML / CSS / JavaScript + localStorage
    └─ 향후: Supabase에서 승인된 데이터 조회

[향후 데이터 파이프라인]
공식 API / 수집 허용 출처 / 기관 제출
    → n8n 수집·스케줄링
    → Gemini 공고문 구조화(필요 시)
    → 필수값·날짜·중복 검증
    → Supabase PostgreSQL
    → SpecSignal 탐색·추천·일정 등록
```

> 수집 대상 사이트의 이용약관·자동 수집 정책·재게시 허용 범위는 실제 운영 전에 확인해야 한다. AI가 확인할 수 없는 날짜·자격 조건은 추측하지 않고 누락값으로 처리한다.

```text

├── index.html                 # 현재 웹 프로토타입 진입점
├── CSS/
│   └── style.css              # 반응형 UI 스타일
├── js/
│   └── app.js                 # 화면 전환·상태·일정·탐색 로직
└── pages/                    # 이전 시안 및 개발 이력 보관
    ├── index.html
    ├── SpecSignal_와이어프레임.html
    ├── SpecSignal_모바일_프로토타입_v0.5_11.03.html
```

> 위 `pages/` 파일명은 읽기 편하도록 표기한 이름이며, 실제 파일명은 저장소에서 확인한다. `pages/`는 실행 진입점이 아닌 **시안·변경 이력 참고 자료**로 취급한다.

## 5. 실행 방법

정적 웹이므로 Python 서버나 별도의 빌드 도구가 필수는 아니다.

1. 저장소를 클론하거나 ZIP으로 내려받는다.
2. 루트의 `index.html`을 브라우저에서 연다.
3. 또는 VS Code Live Server 등 정적 서버로 실행한다.

```bash
git clone https://github.com/byeol0211/PLSAi.git
cd PLSAi
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`에 접속한다. 실제 공개 페이지는 상단의 GitHub Pages 링크를 이용한다.

> **주의:** 기존 다른 SpecSignal 저장소의 `src.web.server`, `.venv`, `requirements.txt`, `tests/` 실행 지침은 이 저장소의 현재 파일 구성과 다르므로 적용하지 않는다.

## 6. 데이터 품질 및 보안 원칙

- 공모전마다 원문 URL과 확인 시각을 저장하고, 마감일 등 주요 필드를 검증한다.
- 신규 등록과 기존 공고 갱신을 구분하고 중복 저장을 방지한다.
- AI 추출 결과는 원문 근거와 비교하고, 불확실한 값은 `null` 또는 검토 대기로 처리한다.
- 실제 DB 연동 시 공개 데이터 조회와 관리자 쓰기 권한을 분리하고 RLS를 설정한다.
- API 키·Supabase 서비스 역할 키를 프론트엔드나 Git 저장소에 포함하지 않는다.
- 기관 제출 데이터는 관리자 검토 후 공개하도록 설계한다.

## 8. 현재 한계

- 현재 루트 코드의 자격증·공모전은 **예시 데이터**이며 실시간 목록이 아니다.
- AI 추천은 **실제 LLM 호출이 아닌 데모 동작**이다.
- 프로필·관심 목록·일정은 **브라우저 localStorage**에 저장되며 서버 동기화되지 않는다.
- 학사일정 조회 및 기관 공모전 등록 제안은 실제 외부 서비스와 연결되지 않았다.
- n8n·Gemini·Supabase 데이터 파이프라인은 **계획 단계**이며 현재 저장소에 구현된 것으로 표시하지 않는다.
